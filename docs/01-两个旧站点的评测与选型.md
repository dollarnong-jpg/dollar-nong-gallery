# 两个旧站点：评测与选型

## 先说清楚一件事

我**没能真正打开**这两个站点。原因有两个，都不是你的问题：

1. 这台机器上找不到这两个仓库的源码，我只能读到你的照片、文档这些素材；
2. 当前环境里，联网抓取和本机浏览器自动化都被安全审批服务的一个配置故障拦住了（报错是审批模型名不匹配），换了几条路都过不去。

所以下面第一部分是根据 **URL 结构** 和 **你的需求** 做的判断。如果我理解错了，把仓库地址或者 `index.html` 发我，我给你逐条改。

---

## 一、从两个 URL 能看出什么

| URL | 对应的仓库形态 | 说明 |
| --- | --- | --- |
| `dollarnong-jpg.github.io/#/` | **用户站**：仓库名必须是 `dollarnong-jpg.github.io` | 每个 GitHub 账号只能有一个，直接挂在域名根目录 |
| `dollarnong-jpg.github.io/dollar-nong-gallery/` | **项目站**：仓库名是 `dollar-nong-gallery` | 可以有很多个，各自挂在 `/仓库名/` 子路径下 |

两个 URL 都以 `#/` 或子路径形式出现，说明两套都在用 **hash 路由**（地址里带 `#`）。这在 GitHub Pages 上是正确的选择，因为前后端不在同一台服务器，没法配置 URL 重写。

所以你原来的"两个模式"，本质上是：

- **模式 A**：整站放在用户站仓库，根目录访问；
- **模式 B**：网站放在独立仓库，挂在子路径访问。

## 二、两种模式的真实差别

| 对比项 | 模式 A：用户站 | 模式 B：项目站 |
| --- | --- | --- |
| 访问地址 | `https://dollarnong-jpg.github.io/` | `https://dollarnong-jpg.github.io/dollar-nong-gallery/` |
| 仓库数量 | 只能 1 个（名字固定） | 可以 N 个 |
| 资源路径 | 用 `/assets/x.js` 或 `assets/x.js` 都行 | **必须用相对路径**，写 `/assets/x.js` 一定 404 |
| 以后想加子站 | 很难，根目录被占满 | 随时新建仓库挂上去 |
| 以后想换域名 | 可以在根目录加自定义域名 | 也可以，但要单独配置 |
| 出问题影响面 | 全站一起挂 | 只影响这一个站 |

**最容易踩的坑**是模式 B 的资源路径。项目站部署在 `/dollar-nong-gallery/` 下面，如果 HTML 里写 `<link href="/assets/style.css">`，浏览器会去 `https://dollarnong-jpg.github.io/assets/style.css` 找，必然 404，页面就变成一堆没有样式的文字。这也是绝大多数"第二个站突然不显示样式"的原因。

## 三、我的结论：两个都别留，合成一个

既然你现在要"重新整理"，那不要在两套之间挑了，直接做一次合并：

**留一个仓库，用项目站的形态（模式 B），把用户站那个仓库腾出来。**

理由：

1. **用户站仓库的名额是稀缺的**。`dollarnong-jpg.github.io` 这个名字只能用一次。哪天你想加个人简介页、接单页、作品博客，都还得占着根目录。把它留白，项目站随便建。
2. **作品站会经常重做**。配色、排版、栏目都会变。放在独立仓库里，改坏了删掉重来，不影响别的。
3. **模式 A 唯一的优势是地址短**。如果你特别在意那个短地址，可以回头再做一次跳转，成本很低。

至于路由和技术栈——**选哪个其实不影响你的核心需求**。你真正要解决的是"怎么上传作品"，这跟挂在哪个域名下没关系。

## 四、关键问题：GitHub Pages 没法"网页上传"

这点必须先讲明白，否则怎么做都会卡住。

GitHub Pages 是**纯静态托管**：它只会把仓库里的文件当成网页发出去。它没有数据库、没有后端、不能接收上传。所以"打开网站，登录，然后拖一张照片上去"这件事，**在 GitHub Pages 上不可能原生实现**。

网上那些"在线管理后台"，实际是两种做法：

- **做法一：网页后台 + 第三方 OAuth 代理**（如 Decap CMS）。页面上的提交按钮其实是往 GitHub 仓库提交文件。缺点是要额外接一个 OAuth 中转服务，配置烦，而且大图上传体验差、失败率高。
- **做法二：本机管理工具**。照片在本机处理（压缩、生成缩略图、写数据文件），然后自动推送到 GitHub。**你不需要把原图传上去，也不需要配任何第三方服务。**

对一个动辄几十 MB 一张的摄影站来说，第二种明显更合适。**我给你做的就是这个。**

## 五、最终形态

```
你的 Mac / 家里的 NAS
        │
        │  原图放在 content/albums/ 里（这个目录可以就是 NAS 上挂载过来的文件夹）
        ▼
   管理台（本机网页，双击启动）
        │  拖拽上传 → 自动压缩 → 生成缩略图和数据文件
        ▼
   web/ 目录（只有压缩后的副本，通常几十 KB 到几百 KB 一张）
        │
        │  点一下「发布到线上」
        ▼
   GitHub 仓库 → GitHub Pages 自动发布
```

三个要点：

1. **原图永远不上传**。网站里只有 900px 的缩略图和 2048px 的大图，一张几百 KB，加载快、不占仓库。
2. **源目录和网站分离**。`content/` 是放照片的地方，可以指向 NAS；`web/` 是生成的产物，只往这个目录推。
3. **两个入口都给你了**。愿意点鼠标就用管理台；懒得开管理台，直接往 NAS 的文件夹里丢照片，挂个自动任务就会自己更新。

## 六、如果我判断错了

如果你原来的两个站其实不是"用户站 + 项目站"，而是比如"同一个仓库的两套主题"或者"两套完全不同的技术栈"，那结论要改。告诉我这三种情况里的哪一种，或者直接把仓库内容给我看：

1. 两个仓库的名字分别是什么？
2. 哪个是你更想保留的风格？
3. 里面的作品照片大概多少张、单张多大？
